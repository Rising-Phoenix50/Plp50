3. Working agreement
Communication
Respond within 24 hours on WhatsApp. Tag relevant members. Escalate blockers immediately — no silent delays.
Task ownership
Every task has a named owner. If blocked, flag it in the board before the deadline, not after.
Transparency
All work visible on GitHub Projects. No private branches without a PR. Progress is team property.
Blocker reporting
Report blockers in WhatsApp + Board simultaneously. Include impact and propose the next step.
Code review
Every PR requires at least one review before merging. Reviews are technical, not personal.
Documentation
Code changes without updated docs are incomplete. Docs are a delivery requirement, not optional.

5. Engineering process — branch naming
All branches follow strict prefixes. No unprefixed branches merged to main.
• feature/ — new user-facing functionality
• fix/ — bug fixes and patches
• chore/ — maintenance, config, tooling
• docs/ — documentation updates only
• review/ — audit-driven change branches
Evidenced in the actual repo: fix/prisma-setup (PR #2). Other branch names weren't visible in PR notification emails — pull the full branch list from GitHub to confirm compliance.
